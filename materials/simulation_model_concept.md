# Концепция имитационной модели движения (гор. −480, шахта «Болашак»)

Версия 0.5 от 24.10.2026 (реализована версия 0.1.2 приложения: многостраничный интерфейс, запуск в браузере без сервера; разделы 12, 15 и 18 обновлены). Основание: решение Dr. Joni 22.10.2026, что первой версией приложения будет имитационная модель движения (Блок 6, вопрос 1). Числа в примерах пересчитаны кодом, допущения помечены «подтвердить». Исходные формулы тяги, циклов СГШО и баланса смены остаются в formulas_and_defaults.md, здесь они только используются.

## 1. Тип модели и параметры прогона

- **Тип:** дискретно-событийная модель (DES). Состояние меняется только в моменты событий (въезд на участок, освобождение участка, начало и конец погрузки, разгрузка, отказ, восстановление), между событиями движение считается формулами.
- **Время:** секунды, горизонт прогона `T = 10,2 · 3600 = 36 720 с` (одна подземная смена), опции: сутки с двумя сменами и технологическими перерывами 3,6 ч, породная смена 08:00–17:00 (540 мин).
- **Режимы:** детерминированный (все времена равны средним, k_v = 0,7) и стохастический (случайные времена погрузки, отказы), в стохастическом режиме выполняется несколько репликаций.
- **Число репликаций** по двухшаговой схеме: пилот `n₀ = 10`, затем `n = ⌈(t₀,₉₇₅;n₀−1 · s / (ε · x̄))²⌉`. При t = 2,262, `s/x̄ = 0,08` и допустимой относительной ошибке ε = 3 % получается n = 37. Здесь x̄ и s — среднее и стандартное отклонение ключевого показателя (число составов за смену) по пилотным репликациям.
- **Воспроизводимость:** `seed_k = seed₀ + k`, одинаковые входные данные и seed дают одинаковый результат.

## 2. Граф и ресурсы

Граф `G = (V, E)`: узлы V (стрелки, сопряжения, разминовки, посты), рёбра E (участки пути). Для ребра e заданы длина L_e (м), уклон i_e (‰), максимальная скорость v_огр,e, тип.

| Ресурс | Ёмкость | Правило |
|---|---|---|
| Блок-участок (однопутное ребро) | 1 состав, одно направление | занят от въезда головы до выхода хвоста, встречный ждёт на разминовке |
| Разминовка | `k_р = ⌊L_разм / (L_п + L_зап)⌋` составов | `L_п = L_лок + n · L_в`, `L_зап` — запас на остановку |
| Пост погрузки (С-14, С-15, С-16, Орт №20) | 1 состав | для погрузки нужен свободный ПДМ |
| ПДМ ST1030 №2 | 1 | один на С-14, С-15, С-16, поэтому посты не работают параллельно, узкое место получается само |
| КДРВ №2 (и №1 после ввода) | 1 состав | `t_разгр = (L_лок + n · L_в + L_ст) / v_ст`, v_ст = 3 км/ч = 0,833 м/с, для 9 ВДР 90 с |
| Ствол (клеть, копёр) | по графику | окна посадки, загрузки миксеров и платформ (данные A8) |

Блок-участок можно разрешить с интервальным следованием в одном направлении, если `I_мин = (L_торм + L_п + L_зап) / v`. По умолчанию ёмкость 1 (консервативно).

## 3. Кинематика состава на ребре

Обозначения: v — скорость на ребре, м/с; a — ускорение при трогании, м/с²; b — замедление при торможении, м/с²; S_норм — нормативный тормозной путь.

1. **Скорость на ребре:** `v_e = min(k_v · v_пасп, v_огр,e, v_доп)`, k_v = 0,7 (допущение шахты: фактических скоростей нет). Ferrit: 0,7 · 20 = 14 км/ч = 3,889 м/с.
2. **Допустимая скорость по тормозному пути:** `v_доп = √(2 · b · S_норм)`. Нормативы S_норм для грузовых и людских составов брать из правил безопасности и инструкции шахты (подтвердить). При b = 0,5 м/с² (допущение) и S = 40 м получается 22,8 км/ч, при S = 20 м 16,1 км/ч, то есть при скорости 14 км/ч ограничение не срабатывает.
3. **Ускорение:** `a = (F_к − M · g · (w₀ ± i)/1000) / (1,1 · M)` (раздел 4 formulas_and_defaults.md). Ferrit, M = 190 т, 55 кН: a = 0,146 м/с² (верхняя граница, реальная настройка контроллера может быть ниже).
4. **Движение без остановки:** `t = L_e / v_e`.
5. **Потери на остановку и трогание:** `Δt = v/(2a) + v/(2b)`. Для Ferrit: 13,3 + 3,9 = 17,2 с на одну остановку. Пути разгона и торможения: `s_a = v²/(2a) = 51,8 м`, `s_b = v²/(2b) = 15,1 м`, ребро короче 66,9 м состав не успевает набрать v.
6. **Короткое ребро** (`L < s_a + s_b`): `v_пик = √(2 · L · a · b / (a + b))`, `t = v_пик · (a + b) / (a · b)`. При L = 40 м: v_пик = 3,01 м/с (10,8 км/ч), t = 26,6 с.
7. **Занятость блок-участка:** `t_зан = (L_e + L_п) / v_e` (участок освобождается, когда его покинул хвост).
8. **Тормозной путь полный:** `S_торм = v · t_реакц + v²/(2b)`; при t_реакц = 1 с и v = 3,889 м/с это 19,0 м.

Уклон гор. −480 принят малым (допущение, 3–5 ‰, подтвердить по пикетажу), условие тяги `n ≤ n_max` проверяется формулами раздела 5 formulas_and_defaults.md при построении заявки.

## 4. Автомат состояния локомотива (Ferrit, руда)

1. `Ожидание заявки` → получение заявки диспетчером.
2. `Порожний ход` к посту погрузки по кратчайшему маршруту с учётом занятости блок-участков.
3. `Ожидание поста` (пост занят другим составом).
4. `Погрузка`: `t_погр.сост = t_пост + n · (t_ц,ПДМ + t_подача)`. По значениям раздела 10 п.7: `2 + 9 · 2,47 = 24,2 мин`. Состав стоит, вагоны подаются по одному.
5. `Гружёный ход` к КДРВ (приоритет у гружёных).
6. `Ожидание КДРВ`.
7. `Разгрузка` (90 с на 9 ВДР).
8. `Порожний ход` на погрузку, цикл замкнут. Для К-14 состояния те же, но пунктом назначения может быть ствол, место погрузки или выгрузки по заявке.

## 5. Диспетчеризация и разъезды

- **Приоритет заявок** (значения по умолчанию, подтвердить): людские по окнам смен, бетон, руда и порода по плану, ТМЦ.
- **Приоритет проезда при конфликте за блок-участок** (порядок проверки): 1) уже занявший участок держит его; 2) груженый состав перед порожним (данные Блока 5); 3) направление к Вентиляционному стволу (Блок 2); 4) очередь по времени подхода (FIFO).
- **Тупик ожидания (deadlock):** граф ожидания «состав → ресурс → состав» проверяется при каждой блокировке. Цикл означает взаимную блокировку, порожний состав с низшим приоритетом отходит назад на ближайшую разминовку. Для маршрутов выбирается разминовка с `k_р ≥ 1` и резервируется до въезда.
- **Назначение локомотива на заявку:** свободный локомотив с минимальным `t_подход` до места погрузки, при равенстве с наименьшей наработкой.

## 6. Погрузка и подсистема СГШО в версии 1

В первой версии самосвалы и ПДМ −402 не моделируются, они задают доступность груза. Остальные ресурсы моделируются полностью.

- Объём в камере `V_к(t)`: `dV_к/dt = λ_пост − Σ m_погр`, `V_к ≥ 0`, начальный запас `V₀` и интенсивность поступления `λ_пост` (т/ч) задаются вручную. Режим изоляции: `V_к = ∞`, тогда рассчитывается только движение.
- ПДМ ST1030 №2 выполняет два вида работ: перегрузка из С-1 и погрузка вагонов. Правило по умолчанию: погрузка вагона при стоящем под погрузкой составе имеет приоритет (параметр).
- Масса груза в вагоне: `m_гр = min(Q_ном, V · k_н · γ_разр)`, ВДР руда 10,4 т, порода 7,6 т (раздел 12.1), контроль перегруза по 15 т.

## 7. Случайные величины и отказы

- **Длительности** (погрузка, подача, разгрузка) в стохастическом режиме: логнормальное распределение со средним m и коэффициентом вариации CV. `σ² = ln(1 + CV²)`, `μ = ln(m) − σ²/2`. Для CV = 0,2 (допущение, заменить по хронометражу): σ = 0,198, для m = 2,47 мин `μ = 0,885`, квантиль 95 % равен 1,36 · m.
- **Отказы и КТГ:** `КТГ = MTBF / (MTBF + MTTR)`, откуда `MTBF = КТГ / (1 − КТГ) · MTTR`. Электровозы КТГ 0,8, MTTR = 60 мин даёт MTBF = 240 мин. СГШО КТГ 0,85, MTTR = 60 мин даёт MTBF = 340 мин. Времена между отказами экспоненциальные, MTTR задаётся (подтвердить).
- **Нельзя применять КТГ дважды:** в стохастическом режиме с отказами рабочее время не умножается на КТГ, в детерминированном режиме `T_эф = (T_см − t_ТО) · КТГ` (раздел 13.1). Ежесменное ТО 2 × 30 мин входит в смену и моделируется как плановое окно простоя.
- **Заявки:** по плану и списку (бетон 10 рейсов, ВГ 100 вагонов, люди 135 + 135 на ствол) или со случайным моментом в окне.

## 8. Выходные показатели

- Число составов и тонн за смену: `Q = Σ m_гр / T`, т/ч. Выполнение плана `P = Q_факт / Q_план`.
- Загрузка локомотива: `k_исп = (T_ход + T_погр + T_разгр) / T_эф`. Время ожидания состава на разъездах `W̄ = (1/N) Σ w_j`, максимум и 95-й процентиль.
- Занятость блок-участка: `ρ_e = Σ t_зан / T`. Очередь на КДРВ и посты, средняя и максимальная.
- Загрузка ПДМ и постов: `ρ = T_занят / T_эф`. Простои по причинам: нет груза, нет вагонов, блокировка, отказ, ТО.
- Для стохастического режима: среднее, 95-процентный доверительный интервал `x̄ ± t · s/√n`, минимум и максимум по репликациям.

## 9. Верификация и калибровка

| Тест | Проверка |
|---|---|
| T1 | один локомотив, нет конфликтов: цикл модели равен `t_погр.сост + t_разгр + 2·L/v + 2·(v/(2a) + v/(2b))`. При L = 2,2 / 2,4 / 2,6 км получается 45,16 / 46,87 / 48,59 мин (без разгона и торможения 44,59 / 46,30 / 48,02 мин). Модель совпадает с формулой с точностью 10⁻³ с и не зависит от числа блок-участков |
| T2 | баланс массы: погружено = разгружено + в пути + в камерах |
| T3 | насыщение при избытке локомотивов: один пост даёт `3600 / t_погр.сост = 2,476` состава/ч (совпадение в пределах 1 %), три поста упираются в предел ПДМ `3600 / (n · t_ПДМ) = 4,535` состава/ч (в пределах 2 %). Два поста дают 94,8 % предела ПДМ, потому что на постановку состава (120 с) ПДМ простаивает |
| T4 | закон Литтла для очереди у КДРВ: `L̄ = λ · W̄`, расхождение не более 2 % |
| T5 | детерминированный прогон дважды с одним seed даёт одинаковый результат бит в бит |

Калибровка по хронометражу рейсов: подбор w₀, v̄ и CV по `MAPE = (100/m) Σ |t_факт − t_мод| / t_факт → min`, приёмка при MAPE не более 10 % (допущение, подтвердить).

## 10. Вычислительная нагрузка и архитектура ядра

- Один рейс состава ≈ 30 событий. За смену 54 рейса (руда 27,8, ВГ 12,5, бетон 10, люди 4) дают около 1,6·10³ событий на прогон, 40 репликаций около 6,5·10⁴ событий. Замер версии 0.1 на Python: смена 1423 события и 3,2 мс на прогон (2,3 мкс на событие), сутки 2839 событий и 6,6 мс. Первоначальная оценка 50–100 мкс на событие была завышена в 20–40 раз. 40 репликаций смены займут около 0,13 с, суток около 0,26 с (без учёта случайных величин и заявок версий 0.3–0.5), параллельный счёт по ядрам пока не нужен.
- Ядро расчёта пишется как независимая от интерфейса библиотека с обменом через JSON (граф, справочники, заявки, результаты). Это позволяет менять интерфейс без переписывания модели. Платформа определена 22.10.2026: Windows, веб-страница (раздел 15).
- Данные модели: граф из DXF (импорт), справочники техники и параметров (правятся вручную), список заявок на смену.

**Пропускная способность звеньев** (страница «Схема», проверка узкого места до прогона). Для изолированного движения, составов в час:

```
r_ЭВ = n_ЭВ·3600 / t_ц;   r_пост = n_пост·3600 / t_погр.сост;   r_ПДМ = n_ПДМ·3600 / (n·t_ПДМ)
r_КДРВ = 3600 / t_разгр;  r_блок = 3600 / (2·t_зан),  t_зан = (L_б + L_п)/v
N_ор = min(r)·T_эф/3600;  потребность плана r_пл = Q_пл / (n·m_в·T_эф/3600)
```

Для параметров по умолчанию: r_ЭВ = 8,96, r_пост = 4,95, r_ПДМ = 4,54, r_КДРВ = 40,0, r_блок = 15,2 состава/ч; узкое место ПДМ ST1030 №2; N_ор = 4,535·7,36 = 33,4 состава (3004 т, 120,2 % плана), потребность плана 3,77 состава/ч, имитация даёт 32 состава. Блок-участок занят два раза за цикл (гружёный и порожний проход), отсюда множитель 2. N_ор ориентир, а не строгая граница: имитация ниже из-за пуска первого цикла и ожиданий, а выше может быть на число составов, стоящих на постах в конце окна и дозагружаемых после него (не больше n_пост): при трёх постах 36 составов против 33,4. Это проверяет тест `test_reference_matches_simulation` (имитация не выше N_ор + n_пост и не ниже 0,9·N_ор).

**Анимация** проигрывает журнал событий одной выбранной репликации (номер seed выбирается). Положение состава вычисляется по тем же формулам, что и расчёт времени (раздел 3). Для ребра длиной L, прохода с остановкой на обоих концах, `τ = t − t_вх`, `T = t_a + t_c + t_b`:

- разгон `0 ≤ τ ≤ t_a`, `t_a = v/a`: `s(τ) = a·τ²/2`;
- равномерное движение `t_a < τ ≤ t_a + t_c`, `t_c = (L − v²/(2a) − v²/(2b))/v`: `s(τ) = v²/(2a) + v·(τ − t_a)`;
- торможение: `s(τ) = L − b·(T − τ)²/2`, `t_b = v/b`.

Пример: L = 500 м, v = 3,889 м/с, a = 0,146, b = 0,5 м/с²: t_a = 26,6 с, t_c = 111,4 с, t_b = 7,8 с, T = 145,8 с.

- Положение на схеме по полилинии ребра из DXF: `P(s) = P_j + (s − c_j)/(c_{j+1} − c_j) · (P_{j+1} − P_j)`, где c_j накопленная длина до вершины j, `c_j ≤ s < c_{j+1}`.
- Положение i-го вагона: `s_i = s_гол − L_лок − (i − 1)·L_в`, с переходом на соседнее ребро графа, если `s_i < 0`.
- Скорость проигрывания k (модельных секунд в реальную секунду). Шаг модельного времени на кадр при 30 кадрах/с равен `k/30`. При k = 600: 20 с на кадр, смена (36 720 с) проигрывается за 61,2 с, сутки (86 400 с) за 144 с. Пользователь выбирает k от 1 до 3600, пауза, шаг по событиям, перемотка.
- Объём журнала: около 1,6·10³ событий × 100 Б ≈ 156 КБ на репликацию, в браузер передаётся только журнал выбранной репликации.

**Графики:**
- накопленный выпуск `Q(t)` против плановой линии `Q_пл(t) = Q_пл · t / T`;
- очередь на КДРВ и постах `L(t)`;
- диаграмма Ганта состояний локомотивов (ход, ожидание, погрузка, разгрузка, отказ, ТО);
- гистограмма времени ожидания на разъездах;
- столбцы загрузки ρ по ресурсам (локомотивы, ПДМ, посты, КДРВ, блок-участки);
- для стохастического режима доверительный интервал `x̄ ± t·s/√n` на столбцах и линиях.

## 15. Архитектура для Windows и роли (реализована в версии 0.1)

Решения Dr. Joni от 22.10.2026: приложение работает на одном локальном компьютере, без доступа по сети; пользователь без пароля, пароль только у администратора; язык русский; многоуровневый доступ будет проработан позже.

- **Клиент:** веб-страница (HTML, JavaScript без внешних библиотек), схема и анимация на Canvas, таблицы и графики в браузере. Работает без интернета.
- **Сервер:** одна программа на Python, только стандартная библиотека (без установки пакетов, годится для компьютера без интернета). Слушает только 127.0.0.1, поэтому по сети страница недоступна. Запуск файлом `run.bat`, остановка закрытием окна.
- **Хранение:** файлы JSON в папке `data` (справочник параметров `reference.json`, хеш пароля `admin.json`, последний расчёт `last_run.json`; файл расчёта игнорируется при несовпадении версии приложения). SQLite и версии наборов данных появятся с версией 0.2.
- **Защита сервера:** проверка заголовка Host и Origin (защита от обращения с других адресов), заголовки CSP (`default-src 'self'`, `base-uri 'none'`, `form-action 'self'`, `frame-ancestors 'none'`: встроенные стили и скрипты не допускаются), X-Frame-Options, nosniff, ограничение размера запроса, защита от выхода за пределы папки `static`, явная таблица типов файлов (на Windows `mimetypes` берёт типы из реестра).
- **Пароль администратора:** хранится как PBKDF2-HMAC-SHA256 (600 000 итераций, случайная соль), минимум 12 символов (при 12 символах из 62 энтропия `H = L·log₂N = 71,5` бита), блокировка на 15 минут после 5 неверных попыток, сеанс 30 минут бездействия, cookie с HttpOnly и SameSite=Strict, права проверяются на сервере при каждом запросе записи. Сброс забытого пароля: удалить файл `data/admin.json` (возможно только при доступе к файлам компьютера).
- **Импорт** DXF и Excel запланирован на версию 0.2: DXF проходит этапы разбор, кандидат графа (узлы, рёбра, длины), проверка администратором, сохранение версии. Справочники Excel загружаются по шаблону (листы: локомотивы, вагоны, ПДМ, самосвалы, параметры, ресурсы), ошибки показываются построчно.

**Вариант без сервера (версия 0.1.2).** Те же страницы открываются прямо в браузере: `web/index.html` по двойному щелчку (`file://`) или по http. Устройство:
- `engine.js`: ядро на JavaScript, построчный перенос `sim/engine.py` (очередь событий на двоичной куче с порядком `(время, номер)` как у `heapq`, те же правила блок-участков, разминовок, постов, ПДМ и КДРВ);
- `local-api.js`: вместо запросов к серверу страницы вызывают `LG_LOCAL.call(метод, адрес, тело)`, который обрабатывает те же маршруты `/api/...`, поэтому код страниц не менялся и не дублировался;
- `params-data.js`: справочник и номер версии, создаются из `sim/params.py` и `sim/__init__.py` командой `tools/gen_params_js.py` (один источник для обоих ядер);
- хранение: `localStorage` (ключи `lg1.*`); если браузер запрещает, данные идут через `window.name` и живут до закрытия вкладки, пользователь предупреждён; сохранённый расчёт содержит только параметры и горизонт, показатели пересчитываются при открытии страницы (прогон занимает 2–20 мс, размер результата до 200 КБ не упирается в квоту хранилища);
- пароль: PBKDF2-HMAC-SHA256 через WebCrypto (600 000 итераций, случайная соль, формат записи совпадает с `admin.json`), сравнение за постоянное время, блокировка на 15 минут после 5 попыток, сеанс 30 минут (хранится в `sessionStorage`, привязан к соли пароля: после смены пароля прежние сеансы недействительны);
- **граница защиты:** в этом режиме пароль защищает только интерфейс. Данные лежат в браузере, и человек с инструментами разработчика может прочитать или заменить их, в том числе пароль-хеш. Защита данных от пользователя компьютера возможна только в режиме с сервером (вопрос E8);
- `crypto.subtle` доступен на странице, открытой как файл, по https и на localhost; по обычному http с другого адреса вход администратора не заработает, об этом выводится сообщение.

| Постов \ ПДМ | 1 | 2 | 3 |
|---|---|---|---|
| 1 | 19 | 19 | 19 |
| 2 (по умолчанию) | 32 | 38 | 38 |
| 3 | 36 | блокировка | блокировка |
| 4 | 35 | блокировка | блокировка |

При параметрах по умолчанию (2 поста, 1 ПДМ) блокировок нет при любом числе электровозов от 1 до 30 (тест `test_no_deadlock_with_defaults_for_any_fleet`), сочетание трёх и более постов с двумя и более ПДМ даёт блокировку (тест `test_deadlock_is_detected_with_3_posts_2_loaders`). Интерфейс показывает красное предупреждение, показатели такого расчёта использовать нельзя. Предлагаемое решение для версии 0.2, когда будет реальная путевая схема: резервировать место на ближайшей разминовке по ходу движения до въезда на блок-участок, тогда состав не останавливается внутри блок-участка. Нужно знать правила, по которым диспетчер шахты разводит встречные составы (вопрос B9 в open_questions.md). Менять ядро до этого не стали: результаты проверок T1–T5 и базового расчёта остаются прежними.

**Сверка ядер.** Набор из 62 заданий: умолчания (смена и сутки), 1–30 электровозов, блокировки (3 поста и 2 ПДМ, 4 поста и 3 ПДМ), 1, 2 и 20 блок-участков, медленный ход, короткая и нулевая ёмкость разминовок, малый КТГ, без перерыва между сменами, без ТО, тяжёлый ПДМ, один вагон и 40 случайных наборов в границах справочника. Сравниваются все поля результата: показатели, ожидания, ресурсы, проверки, ряды, дорожки состояний, схема. Допуск `1e-9` относительно, для полей, округлённых до 0,1 (ряды, дорожки), 0,1. Все 62 набора совпали. Контроль самого теста: после намеренной поломки приоритета при освобождении блок-участка расхождение найдено в 14 наборах из 62.

**Тесты.** Ядро Python 25, сервер 13 (добавлены проверка относительных путей и признака режима), сверка ядер 6, ядро JavaScript 10 (`node --test tests/test_engine.js`: границы параметров, окна, T1 цикл 2812,5 с, баланс массы при 1–30 электровозах, известный результат 32 состава и 2880 т за смену, блокировка при трёх постах и двух ПДМ, детерминированность, схема с ориентиром 33,4 состава, быстродействие). Интерфейс в Chromium: 72 проверки с сервером и 79 проверок в браузерном режиме в трёх вариантах раздачи (`file://`, http, раскладка для публикации с главной страницей-фрагментом в оболочке); добавлены вход и блокировка после 5 попыток, перенос справочника текстом, окно подтверждения, сохранение расчёта между вкладками, работа при запрещённом хранилище. Ошибок в консоли браузера нет. Проверка на Linux, Python 3.13, Node 22 и Chromium, на Windows и в Firefox не запускалась.

**Быстродействие ядра на JavaScript:** смена при умолчаниях 14 мс, сутки 19 мс, сутки при 30 электровозах и 20 блок-участках 20 мс (результат до 194 КБ).

**Известные границы браузерного режима:** пароль защищает только интерфейс (раздел 15); при очистке данных сайта справочник и пароль теряются (для справочника есть перенос текстом); данные привязаны к адресу страницы, другой браузер или другая копия папки начинает с нуля; в Firefox при открытии с диска каждый файл может считаться отдельным источником, и страницы не увидят общие данные (для Firefox используйте http или версию с сервером). Блокировки составов (раздел 17) остаются ограничением ядра в обоих режимах.
